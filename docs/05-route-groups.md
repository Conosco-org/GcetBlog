# Route Groups Explained

## 🗺️ What Are Route Groups?

Route groups in Next.js 15 allow you to organize routes into logical sections without affecting the URL structure. They're denoted by parentheses: `(groupName)`.

## 📁 GCET Blog Route Structure

```
app/
├── layout.tsx                    # Root layout (pass-through)
├── (auth)/                       # Auth route group
│   └── URL: /login, /register
├── (frontend)/                   # Frontend route group  
│   └── URL: /, /posts, /dashboard, /editor
└── (payload)/                    # Admin route group
    └── URL: /admin
```

**Key Point:** The parentheses are NOT part of the URL!

## 🎯 Route Group Benefits

### 1. Layout Isolation

Each route group can have its own layout with different structures:

```typescript
// (frontend)/layout.tsx - Has Header & Footer
<html>
  <body>
    <Header />
    {children}
    <Footer />
  </body>
</html>

// (auth)/layout.tsx - Minimal UI, no Header/Footer
<html>
  <body>
    <Logo />
    {children}
  </body>
</html>

// (payload)/layout.tsx - Payload's admin UI
<html>
  <body>
    <PayloadAdmin />
  </body>
</html>
```

### 2. No URL Pollution

Without route groups:
```
/frontend/posts/my-post  ❌ "frontend" in URL
/auth/login              ❌ "auth" in URL
```

With route groups:
```
/posts/my-post  ✅ Clean URL
/login          ✅ Clean URL
```

### 3. Better Organization

```
Easy to understand:
- (auth)/ contains all authentication pages
- (frontend)/ contains all public-facing pages
- (payload)/ contains CMS admin

vs.

Flat structure - hard to navigate:
- app/login
- app/posts
- app/dashboard
- app/admin
```

## 🔍 Detailed Route Breakdown

### (auth) Group

**Purpose:** Authentication and registration pages

```
(auth)/
├── layout.tsx              # Auth-specific layout
├── login/
│   ├── page.tsx           # → /login
│   ├── LoginForm.tsx
│   └── actions.ts
└── register/
    ├── page.tsx           # → /register
    ├── RegisterForm.tsx
    └── actions.ts
```

**URLs Generated:**
- `/login`
- `/register`

**Layout Features:**
- Clean, minimal UI
- No Header/Footer
- Logo and back button
- Own HTML structure
- Gradient background

**When to add routes here:**
- Password reset page → `(auth)/reset-password/page.tsx` → `/reset-password`
- Email verification → `(auth)/verify-email/page.tsx` → `/verify-email`
- 2FA setup → `(auth)/two-factor/page.tsx` → `/two-factor`

---

### (frontend) Group

**Purpose:** All public-facing and user dashboard pages

```
(frontend)/
├── layout.tsx              # Frontend layout with Header/Footer
├── page.tsx               # → / (homepage)
├── posts/
│   ├── page.tsx          # → /posts (archive)
│   └── [slug]/
│       └── page.tsx      # → /posts/my-post-slug
├── dashboard/             # Protected
│   ├── page.tsx          # → /dashboard
│   └── account/          # 🚧 PLANNED
│       └── page.tsx      # → /dashboard/account
├── editor/                # Protected  
│   ├── page.tsx          # → /editor
│   └── account/          # 🚧 PLANNED
│       └── page.tsx      # → /editor/account
├── [slug]/               # Dynamic pages
│   └── page.tsx          # → /about, /contact, etc.
└── search/
    └── page.tsx          # → /search
```

**URLs Generated:**
- `/` - Homepage
- `/posts` - Post archive
- `/posts/[slug]` - Individual post
- `/dashboard` - Contributor dashboard
- `/dashboard/account` - Contributor settings (planned)
- `/editor` - Editor dashboard
- `/editor/account` - Editor settings (planned)
- `/[slug]` - Dynamic pages (About, Contact, etc.)
- `/search` - Search results

**Layout Features:**
- Full Header with navigation
- Footer with links
- Own HTML structure
- Global providers
- Authentication context

**When to add routes here:**
- New static page → `(frontend)/new-page/page.tsx` → `/new-page`
- Categories → `(frontend)/categories/[slug]/page.tsx` → `/categories/tech`
- Author pages → `(frontend)/authors/[slug]/page.tsx` → `/authors/john-doe`
- User profiles → `(frontend)/profile/[id]/page.tsx` → `/profile/123`

---

### (payload) Group

**Purpose:** Payload CMS admin interface

```
(payload)/
├── layout.tsx              # Auto-generated by Payload
├── admin/
│   ├── [[...segments]]/   # Catch-all for admin routes
│   └── importMap.js       # Auto-generated
└── custom.scss            # Custom admin styles
```

**URLs Generated:**
- `/admin` - Admin dashboard
- `/admin/collections/posts` - Manage posts
- `/admin/collections/users` - Manage users
- `/admin/collections/[collection]` - Any collection
- `/admin/account` - Admin account (Payload built-in)

**Layout Features:**
- Complete Payload UI
- Own HTML/head/body
- Built-in navigation
- User management
- File browser

**⚠️ Important:**
- **DO NOT** manually edit `layout.tsx` - Payload regenerates it
- Customize via `payload.config.ts` and `custom.scss`
- Has its own HTML structure (separate from frontend)

---

## 🔄 Root Layout Strategy

### The Problem

Each route group needs its own `<html>` and `<body>` tags, but Next.js requires a root layout. If the root layout has HTML tags, Payload's layout conflicts with it.

### The Solution

```typescript
// app/layout.tsx - Root layout
export default function RootLayout({ children }) {
  // Just pass through - don't add HTML tags
  return children
}
```

```typescript
// app/(frontend)/layout.tsx
export default function FrontendLayout({ children }) {
  // Has its own HTML structure
  return (
    <html lang="en">
      <body>
        <Providers>
          <Header />
          {children}
          <Footer />
        </Providers>
      </body>
    </html>
  )
}
```

```typescript
// app/(auth)/layout.tsx
export default function AuthLayout({ children }) {
  // Has its own HTML structure
  return (
    <html lang="en">
      <body>
        <Providers>
          <Logo />
          {children}
        </Providers>
      </body>
    </html>
  )
}
```

```typescript
// app/(payload)/layout.tsx (auto-generated)
export default function PayloadLayout({ children }) {
  // Payload's RootLayout has its own HTML
  return (
    <RootLayout config={config}>
      {children}
    </RootLayout>
  )
}
```

## 🛣️ Route Resolution

### How Next.js Resolves Routes

1. User visits `/login`
2. Next.js looks in `app/` for `login/page.tsx`
3. Finds `app/(auth)/login/page.tsx`
4. Ignores `(auth)` in URL
5. Applies layout from `app/(auth)/layout.tsx`
6. Then root layout from `app/layout.tsx`

### Multiple Matching Routes

What if two route groups have the same path?

```
❌ DON'T DO THIS:
app/
├── (auth)/
│   └── login/page.tsx      # /login
└── (frontend)/
    └── login/page.tsx      # /login (CONFLICT!)
```

**Error:** `You cannot have two parallel pages that resolve to the same path`

### Correct Approach

Keep routes unique to their purpose:
```
✅ DO THIS:
app/
├── (auth)/
│   └── login/page.tsx      # /login
└── (frontend)/
    ├── page.tsx            # /
    └── posts/page.tsx      # /posts
```

## 🎯 Adding New Routes

### Adding a Public Page

```bash
# Create the page
src/app/(frontend)/contact/page.tsx
```

```typescript
// src/app/(frontend)/contact/page.tsx
export default function ContactPage() {
  return <div>Contact Us</div>
}
```

**Result:** Accessible at `/contact` with Header and Footer

---

### Adding a Protected Page

```bash
# Create the page
src/app/(frontend)/dashboard/settings/page.tsx
```

```typescript
// src/app/(frontend)/dashboard/settings/page.tsx
export default function DashboardSettingsPage() {
  return <div>Settings</div>
}
```

```typescript
// Update middleware.ts
export const config = {
  matcher: [
    '/dashboard/:path*',  // Already protected
    '/editor/:path*',
    '/admin/:path*'
  ]
}
```

**Result:** Accessible at `/dashboard/settings`, protected by middleware

---

### Adding an Auth Page

```bash
# Create the page
src/app/(auth)/forgot-password/page.tsx
```

```typescript
// src/app/(auth)/forgot-password/page.tsx
export default function ForgotPasswordPage() {
  return <div>Reset Password</div>
}
```

**Result:** Accessible at `/forgot-password` with minimal auth layout

## 📊 Route Protection Summary

| Route Pattern | Access Level | Middleware | Layout |
|--------------|-------------|-----------|---------|
| `/` | Public | ❌ | Frontend |
| `/posts/*` | Public | ❌ | Frontend |
| `/login` | Public | ❌ | Auth |
| `/register` | Public | ❌ | Auth |
| `/dashboard/*` | Contributor+ | ✅ | Frontend |
| `/editor/*` | Editor+ | ✅ | Frontend |
| `/admin/*` | Admin | ✅ | Payload |
